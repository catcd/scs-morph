# scs-morph

**Scientific Claim Stability for MRI Morphometry Pipelines**

`scs-morph` is a Python framework for evaluating MRI morphometry pipelines at the level of **scientific claims**. It converts region-of-interest (ROI) morphometry tables into structured claim cards and evaluates whether the resulting conclusions remain supported under dataset, pipeline, atlas, feature-family, and target perturbations.

The framework is designed for reproducible research audits where no universal gold standard is available and where participant-level neuroimaging data cannot be publicly redistributed.

---

## Overview

MRI morphometry studies commonly report conclusions about aging, cognition, or neurodegeneration from ROI-level features such as cortical thickness, cortical regional volume, and subcortical volume. These conclusions can depend on processing choices, including the dataset, cohort definition, morphometry pipeline, atlas, feature family, target definition, covariate model, and inclusion criteria.

Scientific Claim Stability (SCS) treats the **scientific claim** as the unit of evaluation.

Instead of only asking whether two feature tables agree, SCS asks whether the same scientific conclusion remains:

- supported,
- stable,
- transferable,
- anatomically interpretable,
- and suitable for expert review.

---

## Main features

`scs-morph` supports:

- ROI-level morphometry table processing;
- dataset and metadata harmonization;
- feature-matrix construction;
- claim-card extraction;
- claim-family grouping;
- exact ROI matching;
- group-level anatomical matching;
- stability evaluation;
- claim-score transfer;
- expert and auxiliary LLM review workflows;
- aggregate reporting without redistributing participant-level data.

## Installation

Clone the repository:

```bash
git clone https://github.com/<organization>/scs-morph.git
cd scs-morph
```

Create an environment:

```bash
conda create -n scs-morph python=3.11
conda activate scs-morph
```

Install dependencies:

```bash
pip install -r requirements.txt
```

For editable development installation:

```bash
pip install -e .
```

---

## Configuration

Copy the example path configuration:

```bash
cp configs/paths.example.yaml configs/paths.yaml
```

Edit `configs/paths.yaml` to point to local data and output directories.

The local `configs/paths.yaml` file should not be committed because it may contain machine-specific paths.

---

## Data access

This repository does not redistribute participant-level MRI data, clinical metadata, scan identifiers, raw feature matrices, derived morphometry tables, or participant-level claim scores.

Users must obtain access to the required source datasets through the corresponding data-access procedures and must comply with all applicable data-use agreements.

Participant-level intermediate artifacts generated by this workflow should remain local unless redistribution is explicitly permitted by the relevant data-use terms.

## Workflow

The full workflow is script-based. Each step reads configured inputs and writes explicit output artifacts.

### 1. Audit raw input data

```bash
python scripts/audit_data.py --paths configs/paths.yaml --config configs/datasets.yaml
```

### 2. Parse vector-valued morphometry fields

```bash
python scripts/parse_data.py --paths configs/paths.yaml --config configs/datasets.yaml
```

### 3. Harmonize metadata

```bash
python scripts/harmonize_data.py --paths configs/paths.yaml --config configs/datasets.yaml
```

### 4. Build feature matrices

```bash
python scripts/build_feature_matrices.py --paths configs/paths.yaml --config configs/feature_spaces.yaml
```

### 5. Extract claim cards

```bash
python scripts/extract_claims.py --paths configs/paths.yaml --config configs/claim_extraction_all_main.yaml
```

### 6. Evaluate claim stability and transfer

```bash
python scripts/evaluate_claims.py --paths configs/paths.yaml --config configs/evaluation_pairs.yaml
```

### 7. Export expert-review sheets

```bash
python scripts/export_expert_review.py --paths configs/paths.yaml --config configs/expert_review.yaml
```

### 8. Import completed review sheets

Place returned review files in:

```text
data/expert_review/returned/
```

Then run:

```bash
python scripts/import_expert_reviews.py --paths configs/paths.yaml --config configs/expert_review.yaml
```

### 9. Analyze expert-review results

```bash
python scripts/analyze_expert_reviews.py --paths configs/paths.yaml --config configs/expert_review.yaml
```

## Claim cards

A claim card is a structured object linking a scientific statement to its evidence and provenance.

Each claim card may contain:

* claim identifier;
* claim family identifier;
* claim type;
* claim level;
* source dataset view;
* feature family;
* pipeline;
* atlas or region system;
* target;
* covariate specification;
* signed evidence values;
* support regions;
* support criteria;
* generated claim text;
* validation status.

Claim text is generated from structured templates rather than unconstrained free-form generation.

---

## Stability evaluation

SCS evaluates each source-target claim-family pair using complementary metrics.

For exact ROI matching, metrics include:

* evidence Spearman correlation;
* evidence Pearson correlation;
* weighted evidence overlap;
* top-k rank overlap;
* support Jaccard;
* source-support overlap;
* target-support overlap;
* direction retention;
* sign-flip fraction;
* magnitude drift.

For non-identical feature spaces, SCS maps ROIs to shared anatomical or network-level groups and computes group-level stability metrics.

---

## Claim-score transfer

Claim-score transfer evaluates whether a source claim remains useful in a target setting without refitting.

The source evidence vector is converted into a fixed claim-weight vector. The target feature matrix is then projected onto this vector.

For binary targets, SCS reports:

* oriented AUROC;
* Cohen's d.

For continuous targets, SCS reports:

* Spearman correlation;
* Pearson correlation.

---

## Expert and auxiliary LLM review

The framework includes a review workflow for assessing whether generated claim cards are scientifically usable.

Reviewers score each claim on:

* plausibility;
* clarity;
* faithfulness;
* usefulness;
* confidence.

Reviewers may also provide:

* caution level;
* recommended action;
* corrected claim text;
* comments.

LLM-based review is treated as auxiliary. Agreement with human expert review should be measured empirically and should not be assumed.

Review inputs should not include participant-level MRI data, scan-level feature vectors, clinical rows, subject identifiers, or participant-level derived data.

---

## Responsible use

`scs-morph` is intended for research auditing and scientific reporting. It is not a clinical diagnostic tool.

Generated claims are group-level scientific statements and should not be used for individual diagnosis, prognosis, or treatment decisions.

Users should avoid unsupported causal, mechanistic, or diagnostic interpretations from observational morphometry associations.
